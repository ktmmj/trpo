# Тест-кейсы ServiceDesk (по ТЗ + arch.md + schema.sql + реализованному коду)

Ниже — 26 тест-кейсов, покрывающих все функции из раздела «Функции» ТЗ, нефункциональные требования из «Нефункциональных требований», и реализованный API. Все проверки — через `curl`. Для кейсов, где нет прямого API (адаптивность, цвета, подтверждение, e-mail), указано, что проверяется вручную/на фронте, либо это **вопрос разработчику** (см. раздел в конце).

**Соглашения:**
- `BASE=http://127.0.0.1:8000`
- Токены получаются как в предыдущих ответах: `OP_TOKEN`, `CLIENT_TOKEN`, `ADMIN_TOKEN`.
- «Фактический результат» и «Статус» заполняются при прогоне; в шаблоне — пустые.
- «Доказательство» — имя файла, куда сохраняется вывод `curl` (см. последний раздел о том, как собирать доказательства).

## Сбор доказательств

Единый шаблон для всех curl-кейсов — сохраняем тело и код отдельно:

```bash
save() {
  local name="$1"; shift
  curl -s -o "/tmp/${name}.json" -w "%{http_code}" "$@" > "/tmp/${name}.code"
  echo "$name -> $(cat /tmp/${name}.code)"
}
```

Использование:

```bash
save tc01 "$BASE/health"
save tc04 -X POST "$BASE/auth/register" \
  -H "Content-Type: application/json" \
  -d '{"email":"newclient.tc04@test.ru","full_name":"Тест Клиент","department":"QA"}'
```

Для SQL-проверок (TC-21, TC-30):

```bash
sqlite3 servicedesk.db ".mode box" \
  "SELECT id,ticket_id,status_id,changed_by,note FROM ticket_status_history ORDER BY id DESC LIMIT 5" \
  > /tmp/tc21.history.txt
sqlite3 servicedesk.db "SELECT email, substr(password_hash,1,30) FROM users" > /tmp/tc30.txt
```

Сводный отчёт по всем кейсам:

```bash
printf "%-8s %-6s %s\n" ID CODE NOTE
for f in /tmp/tc*.code; do
  id=$(basename "$f" .code)
  printf "%-8s %-6s %s\n" "$id" "$(cat "$f")" "$f"
done
```
